# 安全解压缩

> 解压之前，先告诉你安不安全。

面向**收到压缩包会先紧张一下的人**：不要求你懂文件格式，只给你一句人话结论、说明这个包从哪来、把伪装包和裹在里面的安装程序拦下来。

纯本地运行，不上传、不联网、不扫描你其他的文件。

---

## 为什么不是「又一个解压器」

| | 需要解压的人 | 有安全焦虑的人 |
|---|---|---|
| 关心什么 | 快不快、格式全不全 | **这个包能不能碰** |
| 卡在哪 | 没有 | 看不懂「可疑」是什么意思 |
| 一句话需求 | 「解开」 | **「你告诉我，我能放心吗」** |

所以这个产品的主界面不是文件列表，是**三行结论**：

```
从微信收到的 · 3 分钟前
✓ 可以放心解开
   48 个文件，解开约 314.6 MB，里面没有程序、没有伪装、没有越界路径。
```

或者：

```
从 Chrome 下载 · 1 小时前
⛔ 危险：包里裹着安装程序
   找到了 1 个可执行内容：照片查看器.app。
   「照片包」里出现安装程序，是骗你装软件最常见的套路。如果你没在等这个程序，建议整包删掉。
```

## 三级结论

| 结论 | 什么情况 | 界面行为 |
|---|---|---|
| **✓ 可以放心解开** | 没有程序、没有伪装、没有越界路径 | 直接给「解压」按钮 |
| **⚠ 先看一眼** | 加密包（影楼常规做法）、看不懂的格式 | 需要密码或确认后继续 |
| **⛔ 别碰** | 伪装成压缩包的程序、包里裹安装程序、压缩炸弹、目录穿越 | **不给解压按钮**，只给结论 |

## 会读出来的东西

| 信息 | 用处 |
|---|---|
| 来源 + 时间 | 谁发的、什么时候（读 macOS 隔离标记） |
| 包注释 | 制作方、拍摄日期、**甚至密码提示** |
| 交付数量核对 | 目录名写「9p」就核对是不是 9 张，少一张立刻报 |
| 逐文件真实类型 | 扩展名说 .jpg，实际是程序 → 检出并撤回结论 |
| 文件名欺骗 | RTL / 零宽字符 / 双扩展名 |
| 内容画像 | 「40 张图片 · 0 个程序」一句话交代清楚 |
| 照片 EXIF | 相机、拍摄时间、是否被修图软件经手、**有没有 GPS 定位** |

实跑示例：

```
  注释      上海XX视觉 2026-05-01 拍摄
            密码：13917177529
  交付核对
     ⚠ 8x6小香槟  9p — 名字写的是 9 张，实际 8 张
  内容      40 张图片
  照片信息  相机 Canon EOS R6 · 拍摄于 2026-10-11 09:55 ~ 09:57
            · 经手过 Adobe Photoshop 26.3 (Windows) · 29 张无 EXIF
```

> EXIF 有两处刻意的边界：**只抽样 60 张**（固实包全解会拖慢），
> **只说「有没有 GPS」，从不打印坐标**（避免把客户住址写进日志和截图）。

## 来源识别

从 macOS 的隔离标记里读出来源，直接告诉用户「这个包是谁发给你的」：

- 微信 / QQ / 飞书 / 邮件附件 / Chrome / Safari / 下载工具
- 顺带给出时间：「3 分钟前」「昨天」

> 这是焦虑型用户最先想知道的信息，比任何技术指标都有用。

## 不做的事（产品边界）

| 不做 | 原因 |
|---|---|
| ❌ 病毒库 / 特征码查杀 | 维护不了，还会给虚假安全感 |
| ❌ 云端查毒 | 包里带客户姓名电话地址，上传即泄露 |
| ❌ 自动删除可疑文件 | 工具只告知，删除权在用户；误删原片要赔钱 |
| ❌ 自动替你打开解压目录 | 被工具「背书」过的文件夹最容易骗人双击 |
| ❌ 压 RAR | RARLAB 授权禁止，只解不压 |

只做**结构性判断**：类型不符、可执行内容、路径穿越、体积炸弹、加密状态。零误报、永不需要更新。

## 支持格式

RAR（RAR4 / RAR5 / 固实 / 分卷 / AES 加密）· ZIP · 7Z · TAR · TAR.GZ · GZ · BZ2 · XZ

## 两种用法

**图形界面**（推荐给目标用户）

```bash
open "/Users/Admin/Downloads/安全解压缩.app"
```

把压缩包拖进窗口即可。解压前先出体检卡片，可疑的包**不提供解压按钮**。

**命令行**（给愿意用终端的人）

```bash
cd pak
cargo build --release
./target/release/pak 照片.rar          # 结论 + 解压
./target/release/pak -C ~/输出 照片.rar
./target/release/pak -p 密码 加密包.rar
./target/release/pak --force 可疑包.zip # 明知有风险仍要解
```

> 内部 crate 名仍叫 `pak`（历史原因，也方便命令行输入），产品对外名称是「安全解压缩」。

## 工程结构

```
pak/
├── src/
│   ├── lib.rs        内核：inspect（体检+结论+来源）/ unpack（解压）
│   ├── sniff.rs      魔法字节识别：认内容，不认扩展名
│   ├── safe.rs       路径净化、可执行识别、体积上限
│   ├── name.rs       中文文件名乱码修复（GBK → 正确 Unicode）
│   ├── extract.rs    RAR/ZIP/7Z/TAR 解压 + 抢救模式
│   └── main.rs       CLI，只负责打印
├── src-tauri/        桌面壳：4 个命令，零业务逻辑
└── ui/index.html     界面：单文件，无构建步骤（?demo=1 可预览）
```

CLI 与 GUI 共用同一个 `lib.rs`，修一处两边都好。

## 实测数据（macOS arm64 / Apple Silicon）

| 项目 | 结果 |
|---|---|
| 315 MB / 41 张照片 RAR5 | **0.99 秒**（系统 `bsdtar` 7.08 秒，快 7 倍） |
| 伪装 `.rar` 的可执行程序 | 拒绝，且**不给解压按钮** ✅ |
| 含木马 `.app` 的 ZIP | 判为「危险：包里裹着安装程序」✅ |
| Zip Slip 穿越包 | 判为危险并拦下，`--force` 后仍不越界 ✅ |
| 100 MB 压缩炸弹（1028:1） | 判为危险 ✅ |
| 截断 RAR（只传了 1/4） | 抢救出 13 个完整文件并说明卡在哪 ✅ |
| GBK 文件名 ZIP | 自动修复成「谷小姐照片.jpg」 ✅ |
| Windows 残留 `$R4N6AX5.jpg` | 自动清理 ✅ |

## 上架 App Store 的就绪度

| 项 | 状态 |
|---|---|
| 无 fork/exec（沙箱必需） | ✅ macOS 路径用 `NSWorkspace`，已在进程内调用 |
| 读取文件来源标记 | ✅ 改用 `libc::getxattr`，不再起 `xattr` 子进程 |
| 沙箱 entitlements | ✅ `src-tauri/entitlements.plist`（默认未启用，见下） |
| 内核是静态链接而非调用 CLI | ✅ 沙箱友好 |
| 签名 + 公证 | ⬜ 需要 Apple Developer（$99/年） |
| **沙箱下的拖拽读取** | ⚠️ **未验证** —— Tauri 不一定处理 security-scoped bookmark |

> 沙箱配置默认**不启用**：`tauri.conf.json` 里加 `"macOS": { "entitlements": "entitlements.plist" }` 才会生效。
> 先启用再验证「拖文件进来还能不能读」，否则用户装了商店版会发现拖拽失效。

## 跨平台现状（诚实版）

| 平台 | 状态 |
|---|---|
| macOS arm64 | ✅ 已打包，17 MB |
| Windows / Linux | ⚠️ 代码可编，但**不能从 macOS 交叉编译** |

`unrar_sys` / `zstd-sys` 需要各平台原生 C/C++ 工具链。正确做法是 CI 矩阵：

```yaml
strategy:
  matrix:
    os: [macos-latest, windows-latest, ubuntu-latest]
```

## 法律边界

- `unrar` 源码许可：允许分发与解压使用，**禁止用于开发 RAR 兼容压缩器**
- 因此本产品只解不压，这是合规前提，不是功能缺失
- 正式分发前请自行复核 RARLAB 的 `license.txt` 原文
